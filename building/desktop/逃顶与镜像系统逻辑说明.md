第一部分：复盘反思（我改了什么，为什么）

我自打过脸一次，必须锁定修正后的结论。 早期我说"软数据没历史、只能向前攒"，后来发现错了一半：FRED 净流动性、CBOE 的 VIX3M/SKEW/VVIX、CBOE PCR、AAII、NAAIM、交易所 BTC 资金费率/基差/DVOL 全都可多年回溯。这彻底改变策略——这批数据要优先接，因为它同时降 live 盲区、又喂历史回测。真正只能向前攒的只剩 GEX、CNN FGI、新闻/社交、精确 mNAV。
我之前把"价格历史回填"埋在 NEXT-2 里，这是错的——它是一切的前置硬阻塞。 本地 FNGU 只到 2025-02，而回测要 2018+；路由腿 BOXX(2022 上市)/DBMF(2019) 更要代理。所以新增 NEXT-0 数据地基，把价格历史、数据版本化、时点对齐三件事先做掉。
最大的隐藏 bug 风险是"时点对齐"(point-in-time)。 周频的 AAII/NAAIM/WALCL 必须按发布日对齐而不是统计周末日，否则回测前视、虚高。我把它提升为一个一等共享工具 + 强制测试。
可复现性我没讲透。 接了网络数据后，回测结果必须钉死在某个**数据快照版本(hash)**上，否则今天和明天跑出不同结果、校准无意义。新增数据 manifest 工单。
校准要诚实。 只有 ~6 年历史、防守信号是稀疏事件，walk-forward 折数很少，网格搜索 + Deflated Sharpe 很容易"显著性归零"。所以选参原则是稳健高原 + 保守宽边际，不是"最优点"，并在报告里明写低置信。别用 DSR 表演掩盖样本不足。
当前单日读数(MSTR EXIT 等)有一部分是盲区升级的假象——别拿它当调参目标。接完数据后会变；唯一裁判是回测。
元模型仍偏早，但弹药比我原以为多。 历史回放 backfill 现在能带上可回溯的软数据特征，训练集更宽；但防守正样本依然少，继续上锁、诚实评估。
修正后的最优路径：

NEXT-0 数据地基（价格历史2018+ / 数据版本化 / 时点对齐）   ← 新增，最先做
NEXT-1 可历史化软数据接入（降盲区 + 喂回测）
NEXT-2 回测引擎补全（2018→2026 + 成本 + walk-forward + 硬阀门历史触发）
NEXT-3 参数扫描与正式校准（稳健选参 + 每模块达标门）
NEXT-4 纯向前软数据（GEX/CNN/新闻/mNAV）
NEXT-5 元模型回放backfill + 训练（带解锁门）
NEXT-6 IBKR 只读对账

签名：def backfill(symbols: list[str], start="2018-01-01", end=None, store_dir="data/history") -> dict[str, BackfillResult]

测试：mock yfinance 返回固定帧，断言幂等续拉不重复、列schema正确、缺口统计正确。
